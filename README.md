> **EN:** An Arabic-first phishing detection platform (URLs, messages, files) with an explainable scoring engine, live threat-intel feeds, RDAP domain-age checks, an AI assistant, accounts with TOTP/email MFA and OAuth (Google/Microsoft/Apple), a paid plan, a REST API and an admin dashboard. Built with zero runtime dependencies on Node.js, and covered by 160+ automated tests.

منصة عربية لكشف التصيد الإلكتروني: فحص الروابط والرسائل والملفات، ومساعد ذكي (CyberBot)، مع حسابات مستخدمين وخطة مجانية وخطة Pro مدفوعة.
مشروع فريق ApexSec، جامعة تكريت، كلية علوم الحاسوب والرياضيات، قسم الأمن السيبراني.

> الفحص يعتمد على قواعد وخوارزميات (Heuristics) وقوائم تهديدات عامة وعمر النطاق. هو ليس مضاد فيروسات، وغياب المؤشرات لا يثبت أن الهدف آمن.

## كيف يعمل محرك الكشف (v4)

المحرك في `public/js/detection-engine.js`، ونفس الملف يعمل بالمتصفح وبالخادم.

**طريقة الحساب:** كل مؤشر له وزن بين 0 و 1، وتُدمج الأوزان بطريقة Noisy-OR:
`الدرجة = 1 − Π(1 − wᵢ)`. فكل مؤشر مستقل يرفع الخطورة، بدون أن تتجاوز الدرجة 100% أو تتضخم من تكرار مؤشرات ضعيفة.

**قابلية التفسير:** كل نتيجة ترجع:
- `indicators`: كل مؤشر مع وزنه الخام و`impact` (كم نقطة تنزل الدرجة لو حذفناه، بطريقة Leave-one-out).
- `confidence`: ثقة الحكم (`high` / `medium` / `low`)، وتكون منخفضة إذا الدرجة قريبة من حدود التصنيف.
- `engineVersion`: رقم إصدار المحرك، حتى تكون النتائج قابلة للتتبع.

## الإعداد على Render (مرة واحدة)

### 1. قاعدة البيانات (إلزامية)
بدونها الحسابات والاشتراكات **تضيع عند كل نشر**.
1. أنشئ حساباً مجانياً على upstash.com ثم **Create Database** (Redis)، واختر منطقة قريبة من Render (Oregon).
2. من تبويب REST API انسخ `UPSTASH_REDIS_REST_URL` و `UPSTASH_REDIS_REST_TOKEN` وضعهما بمتغيرات Render.

### 2. عنوان الموقع
`APP_URL=https://اسم-خدمتك.onrender.com` (بدون / بالنهاية). يُستخدم لروابط الدخول عبر Google/Microsoft/Apple.

### 3. الأدمن
**الدخول بالحساب (الطريقة الموصى بها):** اسم المستخدم ← البريد ← كلمة السر ← كود يصل للبريد. على جهازك نفّذ:
```bash
npm run make-admin -- musab you@example.com
```
يطلب كلمة السر (12 حرفاً على الأقل، لا تظهر على الشاشة) ويطبع سطر `ADMINS=musab:you@example.com:...` تضعه بمتغيرات Render.
يحتاج مزوّد البريد مفعّلاً (القسم 5.5: `BREVO_API_KEY` و `MAIL_FROM`).

افتح `/admin`: اكتب اسم المستخدم ثم البريد ثم كلمة السر، فيصلك رمز من 6 أرقام صالح 10 دقائق ولمرة واحدة، تكتبه وتدخل.
- الخادم يفحص الاسم والبريد وكلمة السر **معاً** بخطوة كلمة السر، ورسالة الخطأ واحدة، فلا يُعرف أي واحد منها غلط.
- الكود ما ينرسل إلا إذا كانت الثلاثة صحيحة، فحتى لو أحد عرف كلمة سرك يحتاج بريدك حتى يدخل.
- 5 محاولات خاطئة تحظر العنوان مؤقتاً، وطلب الرموز محدود، وإعادة الإرسال بعد دقيقة (الكود الجديد يلغي القديم).
- هذه الحسابات ما تقبل الدخول بكلمة السر وحدها. فعّل التحقق الثنائي على حساب البريد نفسه (Gmail/Outlook).

**طرق بديلة (إذا ما عندك حساب بالصيغة أعلاه):** `ADMIN_EMAILS=you@example.com` للدخول بكود البريد فقط،
أو `npm run make-admin -- musab` (بدون بريد) لكلمة سر + تطبيق مصادقة.

**تأكد من عنوان الزائر الحقيقي (مرة واحدة بعد النشر):** حدود محاولات الدخول وإنشاء الحسابات مربوطة بعنوان الزائر. بعد دخولك للأدمن افتح `/api/admin/ipcheck` من نفس المتصفح وشوف `usedIp`. ثم من جهازك نفّذ محاولة دخول خاطئة بعنوان مزوّر:
```bash
curl -s -X POST https://موقعك/api/admin/login -H "Content-Type: application/json" -H "True-Client-IP: 9.9.9.9" -d "{\"username\":\"test\",\"password\":\"x\"}"
```
افتح سجل الأحداث بلوحة الأدمن: إذا ظهرت المحاولة بعنوان `9.9.9.x`، فالترويسة قابلة للتزوير: غيّر `CLIENT_IP_HEADER` لترويسة يضعها الوسيط فعلاً (مثل `cf-connecting-ip` إذا كان Cloudflare الخاص بك أمام الموقع).

### 4. CyberBot (الذكاء الاصطناعي)
أي مزوّد متوافق مع OpenAI. أسهل خيار مجاني: Gemini.
- **Gemini:** أنشئ مفتاحاً من Google AI Studio ثم `GEMINI_API_KEY=...` فقط (النموذج الافتراضي `gemini-2.5-flash`، وتقدر تغيّره بـ `AI_MODEL`).
- **OpenAI:** `AI_API_KEY=sk-...` و `AI_MODEL=...`
- **غيرهم (Groq, OpenRouter...):** `AI_API_KEY`, `AI_MODEL`, `AI_BASE_URL`

إذا تعطّل المزوّد يرد البوت بإجابة محلية (ويفحص الروابط دائماً)، وسبب العطل الدقيق يظهر بلوحة الأدمن ضمن «آخر عطل بمزوّد CyberBot».

### 5. الدفع
| المتغير | مثال |
|---|---|
| `PAY_QICARD` | رقم بطاقة الماستر كارد (Qi Card) لاستلام الدفع |
| `CONTACT_WHATSAPP` | 9647xxxxxxxxx (بدون +) |
| `CONTACT_TELEGRAM` | اسم المستخدم |
| `PAYMENT_NOTE` | تعليمات إضافية تظهر للمشترك |
| `PRICE_USD` / `PRICE_IQD` / `TRIAL_DAYS` | 2 / 3000 / 30 (الافتراضي) |

**طريقة العمل:** المشترك يحوّل ويرسل رقم العملية ← يظهر الطلب بلوحة الأدمن ← تتأكد أن المبلغ وصل فعلاً ← «موافقة وتفعيل» ← يتمدد اشتراكه تلقائياً. تقدر أيضاً تمنح Pro يدوياً أو توقف أي حساب.

### 5.5 تأكيد البريد (موصى به بشدة)
بدونه أي شخص يقدر يسجّل ببريد وهمي. معه: لا دخول قبل الضغط على رابط التأكيد، والشهر المجاني يبدأ عند التأكيد، ويُرفض البريد المؤقت (mailinator وأمثاله)، ويُعدّ `a.b@gmail.com` و`ab+x@gmail.com` نفس الصندوق، والشهر المجاني مرة واحدة لكل صندوق حتى لو حُذف الحساب. ويفعّل أيضاً «نسيت كلمة السر» بالبريد.
1. أنشئ حساباً مجانياً في brevo.com ← Senders & IP ← Senders ← أضف بريدك ووثّقه (رابط يصلك).
2. من SMTP & API ← API Keys أنشئ مفتاحاً (v3).
3. في Render: `BREVO_API_KEY` (المفتاح) و`MAIL_FROM` (البريد الموثَّق) و`MAIL_FROM_NAME` اختياري.
لوحة الأدمن تعرض حالة البريد وآخر عطل. بدون هذه المتغيرات يبقى التسجيل يعمل بدون تأكيد.
(بديل: `RESEND_API_KEY` لكنه يلزمه نطاق خاص موثّق.)

### 5.6 الدخول برقم الهاتف (اختياري)
المستخدم يكتب رقم موبايله العراقي (07XXXXXXXXX) ويوصله رمز من 6 أرقام. إذا ما عنده حساب ينسوّى تلقائياً، ومستخدمي البريد يكدرون يربطون رقمهم من صفحة الحساب. الرسائل تكلف فلوس عند كل المزوّدين، فاختار واحد:
- **Telegram Gateway** (الأرخص، والرمز يوصل داخل تيليگرام): من gateway.telegram.org اشحن رصيد وخذ التوكن ← `TELEGRAM_GATEWAY_TOKEN`.
- **Twilio** (SMS عادي): `TWILIO_ACCOUNT_SID` و`TWILIO_AUTH_TOKEN` و`TWILIO_FROM` (أو `TWILIO_MESSAGING_SERVICE_SID`).
- **بوابة SMS محلية**: `SMS_WEBHOOK_URL` (https) و`SMS_WEBHOOK_TOKEN`. نرسل POST JSON فيه `to` و`message` و`code`.

الحماية: أرقام عراقية فقط (حتى ما ينسرق رصيدك بأرقام دولية غالية)، رسالة كل دقيقة و5 باليوم لكل رقم، 10 بالساعة لكل IP، و`SMS_DAILY_CAP` (افتراضي 300) حد يومي لكل الموقع. الرمز صالح 5 دقائق و5 محاولات. تكدر تطفي الميزة من لوحة الإدارة ← الإعدادات. بدون مزوّد، زر الدخول بالهاتف ما يظهر.

### 5.7 الكشف البصري عن صفحات التصيد (اختياري)
كثير من صفحات التصيد دومينها عشوائي (مثل `x7k2.top`) بس شكلها نسخة طبق الأصل من صفحة دخول فيسبوك أو مصرف. هاي الميزة تفتح الرابط بمتصفح مخفي، تاخذ لقطة شاشة وأيقونة الموقع، وتقارن بصمتها البصرية (pHash) بمكتبة صفحات الدخول الرسمية. إذا الشكل متطابق والموقع مو تابع للجهة = تصيد شبه مؤكد، ويطلع للمستخدم لقطة حقيقية للصفحة.

المتصفح المخفي ياكل ذاكرة، فيشتغل كـ **خدمة منفصلة** (`visual-worker/`) بطابور مهام (صفحة وحدة بالمرة). كل طلبات المتصفح تمر من وكيل حماية يمنع الوصول لأي عنوان داخلي (SSRF)، حتى عبر التحويلات أو الصور.

1. بـ Render: **New → Web Service** ← نفس المستودع ← Runtime: **Docker** ← Dockerfile Path: `visual-worker/Dockerfile` ← Docker Context: `.` ← الخطة المجانية تكفي.
2. بمتغيرات الخدمة الجديدة أضف `VISUAL_WORKER_TOKEN` = مفتاح سري طويل (24 حرفاً أو أكثر).
3. بخدمة الموقع الرئيسي أضف `VISUAL_WORKER_URL` = رابط الخدمة الجديدة (`https://....onrender.com`) و`VISUAL_WORKER_TOKEN` = نفس المفتاح.
4. لوحة الإدارة ← الأمان والنظام ← الكشف البصري ← **حدّث كل البصمات**. أضف صفحات دخول المصارف والمحافظ العراقية اللي تهمك مع نطاقاتها الرسمية.

ملاحظة: بالخطة المجانية الخدمة تنام إذا ما اكو طلبات، فأول فحص بصري بعد النوم ياخذ حوالي دقيقة (الفحص العادي يطلع فوراً والبصري يكمل بالخلفية). تكدر تطفي الميزة من الإعدادات بأي وقت.

### 6. الدخول عبر Google / Microsoft / Apple (اختياري)
عنوان الرجوع (Redirect URI) لكل مزوّد: `APP_URL/auth/<google|microsoft|apple>/callback`

- **Google** (مجاني): Google Cloud Console ← APIs & Services ← Credentials ← OAuth client ID (Web application). أضف عنوان الرجوع، ثم `GOOGLE_CLIENT_ID` و `GOOGLE_CLIENT_SECRET`. اضبط شاشة الموافقة (OAuth consent screen) واجعلها In production.
- **Microsoft** (مجاني): Azure Portal ← App registrations ← New registration ← «Accounts in any organizational directory and personal Microsoft accounts». أضف عنوان الرجوع (Web)، وأنشئ Client secret، ثم `MICROSOFT_CLIENT_ID` و `MICROSOFT_CLIENT_SECRET`.
- **Apple** (يحتاج Apple Developer بـ 99$ سنوياً): أنشئ Services ID وفعّل Sign in with Apple وأضف النطاق وعنوان الرجوع، وأنشئ Key من نوع Sign in with Apple. ثم `APPLE_CLIENT_ID` (الـ Services ID)، `APPLE_TEAM_ID`، `APPLE_KEY_ID`، `APPLE_PRIVATE_KEY` (محتوى ملف .p8 كاملاً).

### 7. Render
- النوع: Docker. Health Check Path: `/healthz`.
- الخطة المجانية تنام بعد الخمول (أول طلب قد يتأخر نحو 30 ثانية).

### 8. الظهور بمحركات البحث (Google و Bing)
1. افتح search.google.com/search-console ← Add property ← **URL prefix** واكتب عنوان موقعك.
2. اختر طريقة **HTML tag**، وانسخ قيمة `content` فقط وضعها بمتغير Render: `GOOGLE_SITE_VERIFICATION`. بعد النشر اضغط Verify.
3. من Sitemaps أضف `sitemap.xml`، ومن URL Inspection افحص `/login` واضغط **Request indexing**.
4. (اختياري) نفس الشي بـ bing.com/webmasters والمتغير `BING_SITE_VERIFICATION` (أو استورد الموقع من Search Console مباشرة).
الفهرسة تاخذ من أيام لأسابيع. نطاق خاص (مثل phishingdetector.iq) يساعد أكثر من `onrender.com`.

## إضافة المتصفح (Chrome / Edge)
الكود بمجلد `extension/`. تفحص كل صفحة **داخل المتصفح** بنفس محرك الموقع، وتحذّر قبل فتح صفحات التصيد، وبيها «افحص هذا الرابط» بالكلك اليمين. ما ترسل الروابط اللي يزورها المستخدم لأي جهة؛ تنزّل فقط قائمة النطاقات المؤكدة (`/api/blocklist`) كل ساعة.

```bash
npm run build-extension -- https://your-site.onrender.com
```
- **للتجربة:** `chrome://extensions` ← فعّل «وضع المطوّر» ← «تحميل إضافة غير مضغوطة» ← اختار `build/extension`.
- **للنشر:** ارفع `build/phishing-detector-extension.zip` على Chrome Web Store Developer Dashboard (رسوم تسجيل مرة وحدة 5$). رابط سياسة الخصوصية: `https://موقعك/privacy`. اشرح استخدام إذن `webNavigation`: «لفحص الصفحة محلياً قبل فتحها، بدون إرسالها لأي جهة».

## مراقبة انتحال الدومين (Pro)
المشترك يضيف حتى 3 نطاقات، ونراقب سجلات شفافية الشهادات (crt.sh) كل يوم، وننبهه بالبريد إذا ظهر نطاق يشبه نطاقه. على خطة Render المجانية الخادم ينام بدون زوار، فالفحص اليومي يشتغل لما يكون صاحي؛ للانتظام استعمل خطة مدفوعة أو Cron Job يطلب الموقع كل يوم.

## نسيان كلمة السر
مع تفعيل البريد (القسم 5.5) يضغط المستخدم «أرسل لي رابطاً على بريدي» في صفحة الدخول. بدونه: من لوحة الأدمن تضغط «رابط كلمة سر» بجانب حسابه وترسله له. الرابط صالح ساعة ولمرة واحدة في الحالتين.

## واجهة API (Pro)
المشترك ينشئ مفتاحاً من صفحة حسابه:
```bash
curl -X POST https://موقعك/api/v1/scan-url -H "Authorization: Bearer pd_..." -H "Content-Type: application/json" -d '{"url":"https://fasebook.com"}'
curl -X POST https://موقعك/api/v1/scan-url -H "Authorization: Bearer pd_..." -H "Content-Type: application/json" -d '{"urls":["https://a.com","https://b.com"]}'
curl -X POST https://موقعك/api/v1/scan-text -H "Authorization: Bearer pd_..." -H "Content-Type: application/json" -d '{"text":"..."}'
```

## الأمان
- كلمات السر مشفّرة بـ scrypt، ولا تُخزَّن الرموز السرية (الجلسات، مفاتيح API، روابط إعادة التعيين) إلا كبصمة SHA-256.
- جلسات بكوكي HttpOnly + SameSite=Lax (+ Secure و __Host- على HTTPS)، وحماية CSRF بفحص المصدر ونوع المحتوى.
- حظر مؤقت بعد محاولات دخول خاطئة (لكل عنوان ولكل بريد)، وحد يومي لإنشاء الحسابات من نفس العنوان.
- الدخول الخارجي: state لمرة واحدة مربوط بالمتصفح، PKCE، nonce، والتحقق من المُصدر والجمهور والصلاحية. البريد غير الموثّق لا يُربط بحساب موجود.
- الحصص تُفرض على الخادم، فلا يمكن تجاوزها بتعديل الصفحة.
- CSP صارم، ورؤوس أمان كاملة، والأدمن بتحقق ثنائي TOTP.
- لا يوجد نظام آمن 100%. فعّل 2FA على GitHub و Render و Upstash، ولا تضع أي مفتاح داخل الكود.

## الخصوصية
- الملفات تُحلَّل داخل متصفح المستخدم ولا تُرفع.
- الروابط والرسائل تُفحص على الخادم ولا تُحفظ، إلا بسجل حساب مشترك Pro (ويقدر يوقفه أو يمسحه).
- فحص عمر النطاق يرسل اسم النطاق فقط إلى rdap.org. قوائم التهديدات تُحمَّل للخادم ولا نرسل روابط المستخدمين لأي جهة.
- رسائل CyberBot تُرسل لمزوّد الذكاء الاصطناعي لتوليد الرد.
