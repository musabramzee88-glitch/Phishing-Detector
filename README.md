# Phishing Detector — منظومة كشف ومكافحة التصيد الإلكتروني

مشروع جامعة تكريت، كلية علوم الحاسوب والرياضيات، قسم الأمن السيبراني.
يفحص الروابط والرسائل والملفات بقواعد وخوارزميات محلية تعمل داخل المتصفح، مع مساعد CyberBot ولوحة إدارة.

> **تنبيه:** الفحص بقواعد (Heuristics)، وليس مضاد فيروسات ولا نموذج ذكاء اصطناعي مُدرَّب. غياب المؤشرات لا يثبت أن الهدف آمن.

## هيكل المشروع

```
server.js            نقطة التشغيل (تربط الوحدات)
server/              كود الخادم
  config.js            الإعدادات من متغيرات البيئة
  http.js              ترويسات الأمان (CSP...) وأدوات HTTP
  rate-limit.js        محددات الطلبات
  static.js            تقديم ملفات public/ فقط
  chat.js              جسر CyberBot (المفتاح على الخادم فقط)
  admin.js             دخول الأدمن (scrypt + TOTP + جلسات)
  stats.js, totp.js    الإحصاءات وسجل التدقيق ورمز التحقق الثنائي
  health.js            مراقب الصحة (ذاكرة + تأخر المعالجة)
  visitors.js          عدّاد زوار تقريبي يحترم الخصوصية
  license.js           مفاتيح الترخيص الموقَّعة (بدون قاعدة بيانات)
  pricing.js           الباقات والأسعار والحدود (عدّل الأرقام هنا)
  billing.js, store.js المبيعات والإيرادات وحفظ السجل (Upstash / ملف / ذاكرة)
  upstash.js           عميل REST لقاعدة Upstash Redis (بدون مكتبات)
  pro.js               الفحص الجماعي المدفوع وفحص المفاتيح
  admin/               صفحات لوحة الأدمن (لا تُقدَّم إلا بعد الدخول)
public/              الموقع العام
  index.html, css/, img/
  js/                  app.js + pro.js + detection-engine.js + error-guard.js
tools/                make-admin.js (حساب الأدمن) و make-secret.js (سر المفاتيح)
tests/               الاختبارات:  npm test
```

## التشغيل محلياً

```bash
npm start          # http://localhost:8080
npm test           # كل الاختبارات
```

يحتاج Node.js 20 أو أحدث. لا توجد مكتبات خارجية.

## المتغيرات (Environment)

| المتغير | الوظيفة |
|---|---|
| `ADMINS` | حسابات الأدمن (يُولَّد بـ `npm run make-admin`). بدونه صفحة الأدمن مغلقة (404). |
| `OPENAI_API_KEY`, `OPENAI_MODEL` | تفعيل ردود CyberBot بالذكاء الاصطناعي (اختياري) |
| `OPENAI_WEB_SEARCH=1` | السماح لـ CyberBot بالبحث (قد يكلّف) |
| `CYBERBOT_GLOBAL_LIMIT` | سقف رسائل CyberBot بالدقيقة لكل الزوار (الافتراضي 120) |
| `LICENSE_SECRET` | سر توقيع مفاتيح الترخيص (`npm run make-secret`). بدونه الاشتراكات مغلقة. تغييره يُبطل كل المفاتيح السابقة. |
| `UPSTASH_REDIS_REST_URL`, `UPSTASH_REDIS_REST_TOKEN` | قاعدة بيانات Upstash لسجل المبيعات (**موصى بها على Render المجانية**). تُنسخ من لوحة Upstash. تُفضَّل على `DATA_DIR` إن ضُبطت. |
| `STORE_PREFIX` | بادئة مفاتيح القاعدة (الافتراضي `pd`)، تفيد لو شاركت القاعدة مع مشروع آخر. |
| `DATA_DIR` | بديل: مجلد سجل المبيعات كملف. على Render يلزم Persistent Disk (مثل `/var/data`) وإلا يضيع عند كل نشر. |
| `CONTACT_WHATSAPP`, `CONTACT_TELEGRAM`, `PAYMENT_NOTE` | بيانات التواصل وتعليمات الدفع بصفحة الباقات (رقم واتساب بالصيغة الدولية بدون +، واسم مستخدم تيليجرام) |
| `TRUST_PROXY=1` | قراءة عنوان الزائر من الوسيط (تلقائي على Render) |
| `AUDIT_STDOUT=1` | كتابة سجل التدقيق كسطور JSON بسجلات الاستضافة (تلقائي على Render، `0` للتعطيل) |

لا تضع أي مفتاح أو كلمة سر داخل الكود أو GitHub. كلها تُضاف من لوحة الاستضافة.

## إنشاء حساب الأدمن

```bash
npm run make-admin -- musab
```

الأداة تطلب كلمة سر (12 حرفاً فأكثر) ولا تعرضها على الشاشة، ثم تطبع سطر `ADMINS=...` وسر التحقق الثنائي.
ضع السطر كمتغير بيئة على Render، وأضف السر لتطبيق Google/Microsoft Authenticator، ثم افتح `/admin`.

## النشر على Render

- النوع: **Docker** (يستخدم `Dockerfile`).
- Health Check Path: `/healthz`
- الخطة المجانية تنام بعد خمول (أول طلب قد يتأخر نحو 30 ثانية). للعمل المستمر: خطة مدفوعة، أو مراقب خارجي يزور `/healthz` كل 5 دقائق.

## الاشتراكات والمبيعات (دفع محلي/يدوي)

**طريقة العمل:** الزبون يتواصل معك (واتساب/تيليجرام) ويحوّل المبلغ (زين كاش، FIB، Qi Card، نقداً...). بعد استلامه تفتح `/admin` > «الاشتراكات والإيرادات» وتصدر مفتاحاً (الباقة + المدة + المبلغ المستلم) وترسله للزبون. الزبون يلصقه بصفحة «الباقات والاشتراكات» فيفتح له **الفحص الجماعي**.

- **الباقات والحدود:** `server/pricing.js` (الأسعار الموجودة أمثلة، عدّلها). الحدود تُفرض على الخادم: Pro حتى 50 رابطاً بالطلب، Enterprise حتى 500، مع حد طلبات بالدقيقة لكل مفتاح.
- **API (Enterprise):** مفتاح الترخيص هو مفتاح الـ API:

```bash
curl -X POST https://موقعك/api/pro/scan-urls   -H "Content-Type: application/json" -H "X-License-Key: PD1-E-...."   -d '{"urls":["https://example.com","https://fasebook.com"]}'
```

- **المفاتيح موقَّعة (HMAC) وتحمل الباقة وتاريخ الانتهاء:** لا تحتاج قاعدة بيانات للتحقق، ولا يمكن تزويرها بدون `LICENSE_SECRET`. التجديد = إصدار مفتاح جديد.
- **الإيرادات:** تعرض اللوحة إيراد الشهر وآخر 30 يوماً والإجمالي **لكل عملة على حدة** (IQD و USD، لا تُجمع معاً)، وعدد الاشتراكات الفعّالة والتي تنتهي قريباً. الأرقام من سجل تدخله أنت يدوياً: الإلغاء لا يحذف المبلغ المسجّل، وأي استرجاع تسجّله بنفسك.
- **التخزين (مهم):** ثلاثة أنواع، تُختار تلقائياً: **Upstash** (قاعدة خارجية، الموصى به) ثم ملف `billing.json` بـ`DATA_DIR` ثم الذاكرة. القرص على Render المجانية **مؤقت** ويُمسح عند كل نشر، لذلك استخدم Upstash أو قرصاً دائماً. المفاتيح نفسها تبقى صالحة حتى لو ضاع السجل (موقَّعة)، لكن سجل المبيعات والإلغاءات هو الذي يضيع، فخذ نسخة احتياطية من اللوحة بعد كل بيع بكل الأحوال.
### إعداد Upstash (مرة واحدة، بدون بطاقة بالخطة المجانية)

1. أنشئ حساباً على upstash.com ثم **Create Database** (Redis) واختر منطقة قريبة من خدمتك (Render عندك بـ Oregon).
2. من تبويب REST API انسخ `UPSTASH_REDIS_REST_URL` و`UPSTASH_REDIS_REST_TOKEN`.
3. أضفهما بمتغيرات Render (Environment). الخدمة تعيد التشغيل وتظهر باللوحة: «مكان حفظ السجل: قاعدة بيانات خارجية (Upstash)».
4. الرمز (Token) سري: لا ترفعه على GitHub ولا ترسله لأحد. إن انكشف، جدّده من لوحة Upstash.

**سلوك الأعطال (مختبر):** إذا تعذر الاتصال بالقاعدة، يرفض النظام تسجيل أي بيع أو إلغاء جديد برسالة واضحة ولا يعرض أي مفتاح (بدل أن يسجّل بيعاً ثم يخسره)، ويعيد المحاولة تلقائياً. التحقق من مفاتيح الزبائن الحاليين والفحص الجماعي يستمران أثناء الانقطاع. الموقع يبدأ ويعمل حتى لو القاعدة طايحة عند التشغيل.

**حدود النسخة المجانية** (من صفحة أسعار Upstash الرسمية وقت الكتابة، راجعها قبل الاعتماد): نحو 500 ألف أمر شهرياً و250MB، والحفظ دائم، **بدون ضمان تشغيل (SLA)** ومن دون تشفير بالقرص. استهلاكنا ضئيل (أمران عند كل تشغيل + أمر لكل بيع أو إلغاء). سياسة الخمول للقواعد المجانية غير مؤكدة بالصفحة التي راجعتها، فتفقّد حالة قاعدتك من لوحة Upstash من وقت لآخر.

- **الخصوصية:** السجل يحتوي أسماء الزبائن التي تكتبها أنت. اكتب الحد الأدنى (اسم أو اسم نشاط)، ولا تضع أرقام هواتف أو بطاقات. اسم الزبون لا يُكتب بسجل التدقيق.

## الاستقرار والمراقبة (Self-healing)

- **المتصفح:** `error-guard.js` يلتقط أي خطأ أو وعد مرفوض، ويبلّغ الخادم (حد 5 تقارير لكل زائر)، ويعرض شريطاً هادئاً. كل أوامر الصفحة تعمل داخل `try/catch`، فخطأ واحد لا يوقف الموقع.
- **الخادم:** كل طلب داخل `try/catch` (يرد 500 عام بدون تفاصيل). الاستثناء غير الملتقط يُسجَّل ثم تُنهى العملية عمداً، وتعيد Render تشغيلها تلقائياً (متابعة العمل بعد استثناء مجهول قد تكمل بحالة فاسدة).
- **/healthz:** يرد 503 إذا بقيت الذاكرة أو تأخر المعالجة بحالة حرجة نحو 30 ثانية، فتعيد Render التشغيل. لوحة الأدمن تعرض الحالة (سليم / متدهور / حرج) وأسبابها.
- **سجل التدقيق:** كل حدث أمني (دخول، فشل، حجب، أخطاء) يظهر بلوحة الأدمن، ويُكتب كسطر JSON بسجلات الاستضافة.
- لا يوجد نظام بنسبة تشغيل 100%. هذا يقلل زمن التوقف ويكشف المشاكل بسرعة، ولا يلغي أعطال الاستضافة أو الشبكة.

## الأمان (ما نفّذناه، وما لا يضمنه أي نظام)

- CSP صارم: لا يُنفَّذ أي سكربت إلا من موقعنا (يمنع حقن الأكواد).
- رؤوس أمان: `X-Frame-Options`, `nosniff`, `Referrer-Policy`, `Permissions-Policy`, HSTS على HTTPS.
- الأدمن: كلمة سر مشفّرة بـ scrypt، تحقق ثنائي TOTP، حظر بعد 5 محاولات فاشلة، جلسات HttpOnly + SameSite=Strict، حماية CSRF.
- الخادم يقدّم ملفات `public/` فقط. حدود لحجم الطلبات ومهلات للاتصالات البطيئة.
- لا يوجد أمان 100% بأي نظام. تبقى مسؤوليتك: تفعيل 2FA على GitHub وRender، حماية بريدك، وعدم مشاركة المتغيرات السرية.

## الخصوصية

الفحص يتم داخل متصفح الزائر. لا نحفظ الروابط ولا الرسائل ولا الملفات. نحتفظ بإحصاءات مجهولة فقط (نوع الفحص ونتيجته).
رسائل CyberBot تُرسل لمزوّد الذكاء الاصطناعي لتوليد الرد.
